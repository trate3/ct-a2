# Alignment between the paper draft and this artifact

Paper source: the authors' draft `impl_section_v5.tex` (and its PDF `Certified_Taps-4.pdf`, which has the same evaluation section). Where the draft is a placeholder, a later revision note for that draft and the newer EQ1 table file are used, and that is said in the row. Status: **match** (code or data reproduces the claim), **partial**, **differs** (the code or the data says something else), or **not covered**.

Scope: this artifact covers the current EQ1 (cost), EQ2 (coding monitors with the execution transcript), EQ3 (coding monitors with only the task and submitted code) and the certification protocol. The travel-agent scenario (current EQ4) and the output-replacement illustration are excluded.

Numbering note: the older draft `impl_section_v5.tex` used EQ3 and EQ4 for other experiments; the newer PDF (`Certified_Taps-5.pdf`) uses the current numbering. That PDF has an editorial inconsistency: it says the evaluation addresses four questions but lists three, and it still contains a travel table that no listed question refers to. This artifact does not decide whether the travel scenario stays in the paper, and it makes no claim about certifying a wrapper.

## Other places where code and paper differ

- The draft's EQ1 caption says Setup "includes model loading and attestation setup". Attestation setup is not included; Setup is model, probe and monitor-server loading only.
- The draft's Table 2 rows are named "E4B: transcript", "Qwen judge reasons", "Activation probe: EMA-max"; the code calls the views `black_box` and `cot`, the monitors `gemma4-e4b`, `qwen3.8-27b-think`, and the pooling `ema_max` (smoothed maximum).
- Numbering: see the note at the top. The final-code comparison is the current EQ3.
